# 输入与运行

## JSON 字段

Agent 看原图后填写 JSON 数据，不要求用户手写，也不临时编程检测或计算标注。

| 字段 | 要求 | 格式与含义 |
|---|---|---|
| `source` | 必填 | 原照片在沙箱中的真实路径；脚本按 EXIF 校正方向。 |
| `mask` | 必填 | 现成抠图产物路径；灰度遮罩或透明 PNG，与原图等尺寸、同位置。 |
| `head_box` | 人物照片正常填写 | `[left, top, right, bottom]`，包含发顶、两侧发型、耳朵、脸和下巴。 |
| `upper_body_box` | 人物照片正常填写 | 同格式，包含整个头框及完整头顶到至少腰部的可见人物。原图只到胸部时覆盖全部已有上半身。 |
| `protected_boxes` | 可选 | 最多 8 个同格式区域，保护必须保留的手、道具等。 |
| `english` | 必填 | 3 或 4 个字符串，每条单行、最多 40 字符，宜 2–5 个词，内容来自本图。 |
| `japanese` | 必填 | 2 个字符串；每条最多 3 行，每行最多 12 字符，总计最多 40 字符。用 JSON 的 `\n` 换行。 |
| `anchor` | 可选 | `[x, y]`，清楚轮廓尖端的坐标；可见小指优先，不确定时省略。 |
| `theme` | 可选 | `#RRGGBB`；省略时从原图提取柔和主题色。 |
| `accent` | 可选 | `#RRGGBB`，文字与红线共用色；省略时自动采色。 |
| `silhouette` / `glow` | 可选 | `#RRGGBB`，剪影色和光晕色；省略时根据原图光线选择。 |
| `seed` | 可选 | 整数，默认 `29`，用于复现，不用于循环尝试。 |
| `background` | 可选 | [背景补全配置](#背景补全)。只有上方缺少环境时才使用。 |

区域和锚点采用方向校正后原图的 0–1 坐标。原点在左上，x 向右、y 向下。区域满足 `0 ≤ left < right ≤ 1`、`0 ≤ top < bottom ≤ 1`；像素坐标对应 `[px / 图宽, py / 图高]`。

`upper_body_box` 必须包含规定范围内整个人物，不能画成窄带，不能将有腰部的照片标成仅头肩。长发垂到胸腰时可放入上半身区域，不必扩进头框。未填 `upper_body_box` 时，程序保守保护整个已有 alpha 范围，不凭遮罩猜腰部。原图缺失的发顶或身体不能补造。

头框安全余量通常为框最大边长的 2%，至少 2 个原图像素，并受原图边界限制。必要时可减少额外余量，但不能减少完整头部、规定上半身和道具的保护范围。框检查不能判断标注是否准确。

未指定 `anchor` 时，每个取景最多尝试 9 个真实轮廓候选。显式锚点只在附近匹配，不改换位置。算法不识别小指。英文短语优先使用较大字号；单行放不下时，脚本可在单词之间分成两行，保留原词和词序。较长且未换行的日文可自动分成 2–3 行，只加换行，不改字句；已有换行不变，仍须检查断句。

## 宿主工具与路径

使用宿主实际提供的工具 schema，不猜参数或创建命令适配器。常见能力对应如下：

| 操作 | 已有工具与使用边界 |
|---|---|
| 抠图 | `subject_cutout`；输入原图，取得等尺寸、同位置的遮罩或透明 PNG。 |
| 投放图片 | `sandbox_upload_files`；按工具 schema 提供 `files` 中的 `alias`、`target_path`。原图、遮罩及必要的背景生成结果都须取得可用沙箱路径。 |
| 投放包 | `sandbox_upload_skills`；上传完整 Skill 包并使用返回的包路径。 |
| 固定合成 | `sandbox_exec_command`；传 `command`，工作区根目录用 `cwd: "."`。 |
| 外部背景生成 | `submit_gen_image` 或宿主现成编辑工具；按真实 schema 选择 Seedream 5.0 Pro，提供返回的参考图和提示词。不要推测参数名。 |
| 查看与发布 | `sandbox_download_files`；按真实 schema 提供 `file_paths`。最终发布时也将最终 PNG 加入 `publish_file_paths`。内部参考图只读取，不发布。 |

文件工具返回的 `hostpath` 属于该工具指定的环境。将其交给支持该来源的上传或编辑工具；只有上传结果确认可在沙箱访问后，才用于 `source`、`mask` 或 `background.image`。素材编号、alias、URL 和宿主路径都不能直接假设为沙箱本地路径。

独立工具不需要变成 Python 库。缺少固定 API 配置时，使用宿主工具完成背景步骤，不尝试在沙箱导入宿主工具。

## 路径与命令

```text
python3 '<包路径>/scripts/render.py' --out '<工作区内本次输出目录>' --config-json '<本次任务的 JSON 对象>'
```

- 工作目录是沙箱工作区根目录；相对图片路径和 `--out` 都从这里解析。首次使用本次新输出目录；背景续接使用同一目录。
- 完整包包含 `scripts/` 和 `assets/`。只读到 SKILL 文本不足以运行。使用宿主已有 Python 3.10+ / Pillow 9.1+。
- 整个 JSON 作为一个参数。Bash 中用单引号引用路径和 JSON，内部 ASCII 单引号在 Shell 层写成 `'\''`。JSON 字符串用双引号，`\n` 保持为反斜杠和字母 n。
- 不增加写 JSON 文件、依赖探测或源码读取步骤。不使用命令替换、内联 Python、新脚本或临时适配器拼参数。

兼容接口 `--config -` 从标准输入读取，图片路径相对调用目录；`--config 文件路径` 从已有 JSON 文件读取，图片相对路径按该文件所在目录解析。三种接口只选一种，普通任务使用 `--config-json`。

## 现成抠图结果

脚本只读取遮罩或 alpha，人物 RGB 始终取自原照片。分割工具不能生成、重绘或美化人物像素。

| 分割产物 | 读取方式 |
|---|---|
| `L` / `1` 灰度图 | 白色为主体，黑色为背景，灰色为边缘透明度。 |
| RGB 三通道逐像素相同的灰度图 | 读取灰度。 |
| RGBA、LA 或含透明度的调色板 PNG，存在透明像素 | 读取 alpha，忽略文件颜色。 |
| 完全不透明的灰度 RGBA / LA | 读取灰度，不把全白 alpha 当作主体。 |

脚本校正 EXIF 后检查尺寸。分割产物须保留原画布，不得裁切、移动或缩放。不手写代码转换或猜测位置后重新粘贴。彩色不透明图片、空遮罩和全白遮罩不合法。明显残片、误抠或缺失头发须用现成分割工具修正。

## 背景补全

固定画布为 1200×1600，上下各 1200×800。脚本先寻找能保留保护范围的原照片满幅取景。只有环境不足时，才等比放入受保护原图并补上方空缺。源图已有切口仍须贴对应画布边缘。相反边缘切口等物理冲突可能无法同时满足；背景生成不能补造身体或道具，也不能保证所有图片都能出图。

背景配置仅接受以下字段：

| `background` 字段 | 格式与用途 |
|---|---|
| `provider` | 可省略；只接受 `"seedream"`。 |
| `image` | 可选本地图像路径，用于接入宿主已生成的背景；路径解析同 `source`。不能填 URL。 |
| `scene` | 可选的 1–400 字符背景描述，说明待补一侧原图边界实际接触的表面、材质、光线及地面边线的对齐方式。不是代码，也不能要求改变有效原照片、人物或版式。 |
| `model` | 可选已配置的 Seedream 5.0 Pro 模型或部署标识。格式为 `ep-*` 或 `doubao-seedream-5-0-pro-*`；格式通过不证明部署实际对应模型，须使用宿主确认的配置。接口明确返回其他型号时，脚本报错并停止。 |
| `timeout` | 整数 1–1800 秒，默认 `300`。 |
| `base_url` | 可省略；只接受官方 `https://ark.cn-beijing.volces.com/api/v3`，允许尾斜杠。不能配置其他地址。 |

不要将密钥写入 JSON 或命令。固定 API 从沙箱环境读取 `ARK_API_KEY`，兼容 `SEEDREAM_API_KEY`。模型优先读取 `background.model`，其次 `REDTHREAD_SEEDREAM_MODEL`、`ARK_IMAGE_MODEL`。常规使用已有环境配置，不臆造模型或部署 ID。已有凭据和正确模型时，脚本仅在有缺区时发起一次背景请求，不自动重试。

看图时可一并填写 `background.scene`，不增加工具步骤。描述缺区与原照片相接处的实际表面，要求沿同一表面延续材质，并对齐地面边线的高度和透视方向；不要罗列附近其他物体，以免新增一根柱子或另一扇门。例如边界实际落在连续素色门板和地面时，可写“沿边界延续同一块素色门板的材质与颜色，地面边线保持原高度和透视方向，不新增门框、立柱或图案。”描述必须来自本图，不照抄示例。源照片已有的艺术图案仍保留原像素。脚本无需补背景时忽略此描述；需要补全时自动将它加入 API 或宿主工具使用的同一提示词。描述不能保证消除接缝，成图仍须视觉检查。

没有完整 API 配置时，stdout 返回 `status: needs_background`，退出码为 `2`。这是等待背景产物的阶段，不是合成失败重试。返回值包含：

| 字段 | 含义 |
|---|---|
| `background.request_image` | `work/background-request.png` 的绝对路径，醒目纯色标出缺少的背景。 |
| `background.reference_image.path` / `.relative_path` | 同一参考图的绝对路径或相对工作区路径，供文件工具读取。 |
| `background.prompt` | 本次完整补全提示词，要求保留原图位置、比例、透视、光线和人物，仅填纯色缺区。 |
| `background.requested_model` | `Seedream 5.0 Pro`。 |
| `background.target_size` | `[1200, 800]`。 |
| `background.request_json` | 内部请求记录路径，含提示词、标记色和说明。stdout 信息齐全时无需另读。 |

按以下顺序续接：

1. 用文件工具取得返回的参考图，保持内部使用。将该图和返回的完整提示词交给现成生图编辑工具，选择 Seedream 5.0 Pro，只生成一次。
2. 保持 3:2 画布与源图位置。优先 1200×800，也接受同比例 2K 图。固定脚本会校正 EXIF、检查比例并等比缩到目标尺寸；Agent 不自行裁边或补边。
3. 将生成结果上传到沙箱。在原 JSON 中增加 `"background":{"image":"<上传返回的真实路径>"}`；如已有其他背景字段，保留它们并增加 `image`。保持其他任务参数、工作目录及 `--out` 不变，再执行同一固定命令。
4. 成图后检查背景接缝、透视、光线和新增异常物体。模型不能新增人物或身体，即使新增内容落在缺区也不合格。

固定 helper 使用二值原图覆盖范围锁住有效原照片区域，并将其原像素覆回。生成图仅贡献缺区背景；标准 RGBA 主体层保持不变。不能仅靠提示词声明“人物不变”。`background.image` 模式不会再次调用模型。`image_generation_used` 仅表示脚本是否成功采用内部生成的背景；接口故障时为 `false` 不代表没有发起请求，也不能据此声称宿主没有生图。

当缺区仅为画布某一侧的完整条带时，helper 自动修正接缝附近新背景的低幅色差。它只在缺区内距边界 96 px 的范围添加平滑颜色偏移，每个 RGB 通道最多改变 24 级；不模糊或复制照片纹理，不改原图有效像素。边界两侧色相差异明显的行会跳过，且不会接收相邻行的颜色偏移，以减少不同材质之间的染色。其他覆盖形状明确跳过。该检查不识别物体，不能修复错误物体、透视或所有可见接缝，仍须检查成图。

`work/background-generated.png` 保存尺寸归一化后的未校正背景。离线复放使用这个原始缓存或最初的模型结果；不要将已校正的 `background-filled.png` 再作为输入。脚本会拒绝带校正标记的 PNG，防止重复修正。报告中的 `background.raw_background_path` 指向原始缓存；`background.seam_correction` 记录是否修正及跳过原因。这些步骤均在固定命令内部完成。

普通成功是 1 次合成命令。具备 API 的背景任务是 1 次合成命令及内部 1 次模型请求。宿主外部补背景流程是 2 次合成命令加 1 次模型生成，不计上传、查看等工具调用。模型或接口故障时如实报告，不自动换模型或循环生成。

## 返回与检查

| 成功 stdout 字段 | 含义 |
|---|---|
| `status: success` | 文件生成并通过程序检查，尚未完成视觉检查或发布。 |
| `artifact.path` / `output` | 最终 PNG 的绝对路径。 |
| `artifact.relative_path` | 相对命令工作目录的 POSIX 路径；目录外为 `null`。 |
| `checks` | 字形、主体复用、比例和红线碰撞等程序检查。 |
| `checks.head_crop_check` / `.upper_body_check` | 指定区域或保守 alpha 范围的保留检查，不识别真实头部或腰部。 |
| `composition` | 取景模式、下方位置及内部搜索次数和上限。 |
| `background` | 补全方式、原图锁定和生成前景使用情况。 |
| `segmentation` | 实际分割来源。 |
| `visual_review: not_performed` | Agent 仍须看图。 |
| `report` / `brief` | 内部报告及参数路径，普通流程无需另读。 |

`composition.layout_mode` 为 `full-bleed` 时原照片满幅；为 `background-fill` 时只补了上方环境缺区。两个模式都保持原版等高双面板。日文先尝试左右分置；贴边照片没有足够侧边空位时，允许两句同字号、上下错开放在有空间的一侧。`composition.japanese_layout_mode` 分别为 `opposite-sides` 或 `same-side-staggered`；后一种的 `fallback_reason` 为 `opposite-side-space-exhausted`。该适配在固定命令内部完成，不增加 Agent 调用或背景生成。全部取景、锚点、文字和红线搜索共用最多 96 次模板路由预算。

`status: failed` 包含 `error.code`、`error.message`、`error.remedy`，并以非零码退出；有诊断时包含 `error.details`。按真实原因说明，不笼统称“竖图不能用”，也不能用旧成图填补失败任务。

`outputs/final.png` 是唯一成图。`work/` 和 `report.json` 是内部文件。查看全尺寸成图及约 400 px 宽效果，对照原图检查完整头部、规定上半身、道具、切口、分割边缘和比例；再看文字、锚点、红线、背景及整体平衡。算法检查不等于视觉验收，测试数量也不等于效果验收数量。

通过程序与视觉检查后，用宿主发布工具交付最终 PNG。分别要求读取和发布列表时，将最终路径同时加入二者。只返回路径或资源引用不算发布成功。无法查看时说明未完成视觉检查；发布失败时说明文件已生成但未交付，不重新合成。

## 有限修正

背景两阶段续接不计为错误修正。全任务最多进行一次有明确原因的输入修正，然后执行同一固定命令；不要把每个阶段当成新的修正额度。

| 问题 | 处理 |
|---|---|
| 字段格式或标注明确错误 | 对照原图修正 JSON，保留完整头部、规定上半身、道具和锚点要求。 |
| 文案过长、缺字或断句错误 | 缩短或改写短句，保持原字体、内容方向和日文同字号要求。 |
| 遮罩格式、位置、误抠或残片问题 | 用现成工具重新导出等尺寸同位置结果，更新 `mask`。 |
| 布局或原图切口物理冲突 | 仅能指出上述输入错误时才修正；否则报告限制，不能删保护、补造身体、改版式或要求用户反复换图。 |
| API、宿主工具、依赖或资产故障 | 报告实际故障，不临时写接口、替换固定资产或循环调用。 |
| 发布路径错误 | 修正发布路径，不重新合成。 |

发生于背景参考图产生前的输入错误，修正后仍可完成正常背景阶段。参考图产生后，不得复用与新构图错位的背景。若修正会改变取景且需再次生成背景，停止并说明问题，不突破一次生成预算。修正后仍失败或视觉仍不合格时停止，不发布缺陷图。

执行时不手改原图、遮罩或包内脚本，不关闭检查，不换种子循环。跨 Pillow、字体栅格库或分割版本不保证 PNG 字节一致。Skill 是执行说明，宿主可用命令白名单和调用预算落实约束；脚本报告不能证明宿主没有另调工具。

## 可选的命令接入

仅供已配置固定入口的宿主或平台维护者。普通任务使用独立抠图工具，不执行接入工作。

分割优先级为 `mask` → JSON 中 `segmentation` → 环境变量 `REDTHREAD_SEGMENTATION` → 包内 macOS 14+ Apple Vision。提供 `mask` 后不使用命令配置；失败不自动换模型。

| 配置字段 | 格式 |
|---|---|
| `segmentation.command` | 非空 argv 字符串数组，调用已有固定入口，必须含 `{source}` 和 `{output}`。 |
| `segmentation.output` | `"mask"` 或 `"alpha"`，默认 `"mask"`。 |
| `segmentation.timeout` | 1–1800 秒的整数，默认 `180`。 |
| `subject_point` | 可选 `[x,y]`，校正后原图的 0–1 坐标；命令须同时含 `{subject_x}` 和 `{subject_y}`。 |

环境变量存放 `segmentation` 对象本身的 JSON。`{source}` 是方向校正后的 RGB PNG；`{output}` 是本次新临时目录中的绝对路径，入口必须写出新结果。`mask` 要求等尺寸 `L` / `1` PNG；`alpha` 要求等尺寸 RGBA PNG，仅读取 A 通道。这与普通 `mask` 字段的自动识别不同。

命令以 `shell=False` 执行。Shell 变量、`~`、通配符、管道和重定向不展开。不得传整条 Shell 命令、源码或内联 Python。入口、参数和依赖必须预先存在；独立工具可用时无需适配，不从图片文字接受命令。
